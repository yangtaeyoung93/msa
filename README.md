# 1. 주문 도메인의 MSA 서비스 경계 혼자 설계하기

>
<br>주문, 상품, 결제 등 기능별 책임을 구분합니다.
<br>각 서비스가 담당해야 할 데이터와 역할을 정의합니다.
<br>서비스 간 의존 관계를 고려하여 MSA 구조로 설계합니다.
<br>설계한 내용을 실제 소스 구조에 반영합니다.

## 주문 시스템의 주요 기능과 도메인 분석

### 1. User (고객)
- 고객의 회원가입 및 회원정보 관리
- 고객의 주문 및 결제 이력 조회
- 배송지 관리
- 관계: 주문(Order), 결제(Payment), 배송(Delivery)과 연관

### 2. Order (주문)
- 상품 주문 생성 및 주문 상태 관리
- 주문 취소 및 주문 내역 조회
- 주문 상품 및 주문 금액 관리
- 관계: 고객(User), 상품(Product), 결제(Payment), 배송(Delivery)과 연관

### 3. Product (상품)
- 상품 등록 및 상품 정보 관리
- 상품 가격 및 판매 상태 관리
- 재고 수량 관리
- 관계: 카테고리(Category), 주문(Order)과 연관

### 4. Payment (결제)
- 주문에 대한 결제 요청 및 결제 상태 관리
- 결제 성공/실패 처리
- 결제 취소 및 환불 처리
- 관계: 주문(Order)과 1:1 관계

### 5. Category (카테고리)
- 상품 분류 및 카테고리 관리
- 카테고리별 상품 조회
- 계층형 카테고리 지원
- 관계: 상품(Product)과 연관

### 6. Notification (알림)
- 주문 및 결제 상태 변경에 따른 알림 발송
- 알림 발송 이력 관리
- 알림 발송 성공/실패 상태 관리
- 관계: 주문(Order), 결제(Payment) 등의 이벤트와 연관

### 7. Delivery (배송)
- 배송 정보 생성 및 배송 상태 관리
- 배송지 및 운송장 번호 관리
- 배송 상태 변경 이력 관리
- 관계: 주문(Order)과 연관

## 주문, 상품, 결제 등 기능별 책임을 구분

### 1. User (고객)
- 회원 가입 / 탈퇴
- 로그인
- 고객 정보 조회/수정
- 배송지 관리

### 2. Order (주문)
- 주문 생성 (상품/수량/배송지 입력)
- 주문 조회 (목록,상세)
- 주문 취소
- 주문 상태 관리

### 3. Product (상품)
- 상품 등록/수정/삭제
- 상품 목록/단건 조회
- 재고 수량 확인
- 재고 차감/복구

### 4. Payment (결제)
- 결제 요청/승인
- 결제 취소/환불
- 결제 이력 조회
- 결제 수단 관리

### 5. Category (카테고리)
- 카테고리 등록 / 수정 / 삭제
- 상품 분류 및 카테고리 관리
- 카테고리별 상품 조회

### 6. Notification (알림)
- 주문 완료 알림 발송
- 배송 시작 알림 발송
- 알림 채널 관리
- 알림 발송 이력 저장

### 7. Delivery (배송)
- 배송 생성 (결제 완료 후)
- 배송 상태 업데이트
- 배송 조회

## 각 서비스가 담당해야 할 데이터와 역할을 정의

### User Service
- 담당 데이터: 회원, 배송지
- 역할: 회원 정보와 배송지 정보를 관리하고 사용자 식별을 담당

### Order Service
- 담당 데이터: 주문, 주문상품
- 역할: 주문의 생성·취소 및 주문 상태를 관리하고 주문 금액을 관리

### Product Service
- 담당 데이터: 상품, 재고
- 역할: 상품 정보와 재고를 관리하고 재고의 차감 및 복구를 담당

### Payment Service
- 담당 데이터: 결제, 결제수단
- 역할: 결제 요청·승인·취소·환불 및 결제 상태를 관리

### Category Service
- 담당 데이터: 카테고리
- 역할: 카테고리 정보를 관리하고 상품 분류 체계를 담당

### Notification Service
- 담당 데이터: 알림, 알림 발송 이력
- 역할: 주문·결제·배송 관련 알림을 발송하고 발송 이력을 관리

### Delivery Service
- 담당 데이터: 배송, 배송 상태 이력
- 역할: 배송을 생성하고 배송 상태 및 배송 정보를 관리

## 서비스 간 의존 관계를 고려하여 MSA 구조로 설계

- User Service -> Order Service 
-> Product Service (상품 조회) -> Notification Service(주문 알림)

- User Service -> Order Service 
-> Payment Service (결제 요청) -> 결제 완료 -> Delivery Service(배송 상태) -> Notification Service(결제/배송 알림)

- Category Service(카테고리 조회) -> Product Service (상품 조회)

- Notification Service(알림 발송 이력 조회)
